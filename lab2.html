The story so far

Sales wants Velo: an assistant on the website and in the car that answers like a good service advisor, never bluffs about warranties, and can hand a tidy ticket to the service team. You have a deployed model from Lap 0. Now you shape it.

Part 0The idea in five minutes

System prompt (instructions)The message the user never sees: who the model is, what it may and may not do, how to answer. In the Foundry playground this is the Instructions box. Most "the bot behaves badly" problems are system-prompt problems.
User promptThe question or task. Good user prompts give context, say what format they want, and give an example when the format matters.
Conversation historyPrevious user and assistant messages sent back with every call. That is the model's only memory. "New chat" clears it.
Few-shot examplesTwo or three worked examples inside the prompt. The cheapest way to teach a format or a classification scheme; no training needed.
GroundingPutting the facts the answer must come from inside the prompt (or giving an agent a search tool), and instructing "answer only from this". The cure for invented warranty terms.
Structured outputAsking for JSON (and enforcing it with response_format) so a program, not a human, can read the answer.

A system prompt is a job description. A user prompt is a ticket. History is the only memory.

Three ways to talk to the same deployment, which you will use in that order: the playground (click), the REST API with curl (see the raw JSON), and the Foundry SDK from Python (the lightweight client the exam describes).

🎯
Exam lens

"Effective" prompts on the exam means: a clear role and constraints in the system prompt, specific user prompts with context and desired format, examples for tricky formats, and grounding data for facts. Parameters: temperature and top_p control randomness, max tokens bounds length and cost, stop sequences end output. The SDK pattern to recognise is AIProjectClient + DefaultAzureCredential + get_openai_client() + chat.completions.create(model=<deployment name>, messages=[…]).

Part 2Shape Velo in the playground

  1. Open ai.azure.com (with New Foundry on), open your project, and go to Discover → Models → gpt-4.1-mini. If Lap 0's deployment exists, select it (Open in playground); otherwise select Deploy and keep the defaults. The model playground opens; hide the left navigation with the button at the bottom of it to get room.

  2. Ask, with no instructions: My Summit's tire pressure light came on this morning. What should I do? Read it. Reasonable, generic, and it does not know what a Summit is.

  3. Select New chat. In the Instructions box on the left, paste the system prompt we used:

    You are Velo, the friendly in-car and dealership assistant for Velocity Motors. Be concise, warm, and practical. Use plain language. If a question involves safety, put the safety step first. If you do not know something specific about Velocity Motors, say so.

    Ask the tire-pressure question again. Now the safety step comes first and it signs off as the dealer. This is what we got from the API with the same prompt (temperature 0.4):

  4. Ask a follow-up without repeating context: And if it comes back on tomorrow? The model answers in context because the playground resends the conversation. Select New chat and ask the same follow-up: now it has no idea what "it" is. That is history, made visible.

  5. Parameters. Open the parameters panel (the sliders icon, or the Parameters tab next to Instructions). Set Temperature to 0, clear the chat, and ask three times: Write a six-word tagline for the Velocity Volt electric sedan. Reply with the tagline only. Then set Temperature to 1.3 (or the maximum the slider allows) and ask three more times. Compare with our run:

    Also look at Max response (output tokens; set it to 20 and watch the answer get cut mid-sentence) and Top P. Put temperature back to about 0.5 for the rest of the lap.

  6. Select View code (sometimes Call model or </> Code) at the top of the chat pane. Choose Python. The portal writes the exact call you just made, with your instructions and parameters. Keep this tab open; Part 5 is a cleaner version of it.

Part 3The same call as raw HTTP

Underneath the playground is one REST endpoint. Seeing it once makes every SDK obvious. The messages array carries the roles; the response has choices (the answers) and usage (the tokens you pay for).

curl -s "$AOAI_ENDPOINT/openai/deployments/$CHAT_MODEL/chat/completions?api-version=2024-10-21" \
  -H "api-key: $KEY" -H "Content-Type: application/json" -d '{
  "messages": [
    {"role": "system", "content": "You are Velo, the Velocity Motors assistant. Be concise."},
    {"role": "user", "content": "Write a six-word tagline for the Velocity Volt."}
  ],
  "temperature": 0.7, "max_tokens": 40
}' | jq '{answer: .choices[0].message.content, usage}'
💡
Reading the bill

The concierge answer above cost 81 prompt tokens and 83 completion tokens. At gpt-4.1-mini's list price (about $0.40 per million input tokens and $1.60 per million output; check the catalog for today's numbers) that is roughly $0.00017. A thousand customers a day asking five questions each is about a dollar. Images and long documents cost more because they are more tokens.

Part 4Stop Velo from bluffing · grounding

  1. In the playground (temperature 0.2, instructions back to the plain Velo prompt), ask: How long is the warranty on the Velocity Volt battery, and does it transfer to a second owner?

    Our run invented a confident, specific, wrong answer: "The Velocity Volt battery comes with a 2-year warranty. However, this warranty is non-transferable and applies only to the original owner." There is no such warranty; the model has never heard of Velocity Motors. This is a hallucination, and a customer would believe it. Remember this moment: it is the reason Lap 3 exists.

  2. Now ground it. Replace the Instructions with: Answer ONLY using the provided context. If the answer is not in the context, say you don't know. Cite the section number. Then paste this as the user message, context first:

    Context:
Velocity Motors Warranty Guide (excerpt, 2026 edition)
Section 4.2 High-voltage battery (Velocity Volt): covered for 8 years or 100,000 miles, whichever comes first, against defects and against capacity loss below 70% of original.
Section 4.3 Transferability: all Velocity warranties transfer automatically to subsequent owners at no cost for the remainder of the original term.
Section 4.4 Exclusions: damage from flooding, racing, or non-approved chargers is not covered.

Question: How long is the warranty on the Velocity Volt battery, and does it transfer to a second owner?

    Now the answer is right and cites 4.2 and 4.3:

  3. Ask one more question with the same context: Does the warranty cover a cracked windshield? A well-grounded model says it does not know from this excerpt. In Lap 3 you will automate the "paste the right section" step with file search.

Grounding gives the model something to be right about.And when the context is silent, "I don't know" is not a failure. It is the feature you paid for.

Part 5Make the answer machine-readable · JSON and few-shot

  1. JSON output. Instructions: Extract a service request from the customer message. Return JSON with keys: customer_name, vehicle, issues (array), urgency (low|medium|high), preferred_time, location, phone, suggested_department. Temperature 0. User message:

    Hi, this is Dana Whitfield. The infotainment screen on my 2024 Velocity Strata keeps rebooting, maybe 3 times a day, and now the backup camera is black. I'm in Dayton. Can someone look at it this Thursday afternoon? Call me at 937-555-0142. Thanks!

    In code you would also pass response_format={"type": "json_object"}, which guarantees valid JSON. Our result:

  2. Few-shot classification. Instructions: Classify each customer comment into exactly one department: Sales, Service, Finance, Product. Reply with the department only. Then, in the chat, give two examples as if they were previous turns (type the comment, and when the model answers, correct it if needed), or simply put the examples in the instructions:

    Examples:
"The lease paperwork took three hours." → Finance
"The brakes squeak after the recall work." → Service

    Now classify: The salesperson never called me back about the Ridge. · The cupholders are too small for my mug. · My monthly payment went up without warning.

Part 6Your first chat app with the Foundry SDK

The playground is for exploring; a product needs code. The Foundry SDK (azure-ai-projects) connects to your project endpoint with your own identity, then hands you an OpenAI-compatible client. No key in the code.

  1. In Cloud Shell, get the script (all pit-crew scripts are in pit-crew-scripts.zip; this fetches just one):

    curl -sO https://varoonsahgal.github.io/az901/pit-crew/chat_client.py
cat chat_client.py
    """Lap 2 · A lightweight chat client built with the Foundry SDK.

Run:  python chat_client.py "your question"      (or no argument for an interactive loop)
Needs: pip install azure-ai-projects azure-identity   and   az login
Env:   PROJECT_ENDPOINT  (Foundry project endpoint, e.g. https://<resource>.services.ai.azure.com/api/projects/<project>)
       CHAT_MODEL        (deployment name, default gpt-4-1-mini)
"""
import os, sys
from azure.identity import DefaultAzureCredential          # uses your az login — no keys in code
from azure.ai.projects import AIProjectClient

endpoint = os.environ["PROJECT_ENDPOINT"]
model = os.environ.get("CHAT_MODEL", "gpt-4-1-mini")

project = AIProjectClient(endpoint=endpoint, credential=DefaultAzureCredential())
client = project.get_openai_client()                        # an OpenAI-compatible client, already authenticated

SYSTEM = ("You are Velo, the friendly assistant for Velocity Motors dealerships. "
          "Be concise and practical. Safety first. If you don't know a Velocity-specific fact, say so.")
history = [{"role": "system", "content": SYSTEM}]

def ask(text):
    history.append({"role": "user", "content": text})
    r = client.chat.completions.create(model=model, messages=history, temperature=0.5, max_tokens=300)
    answer = r.choices[0].message.content
    history.append({"role": "assistant", "content": answer})
    print(f"\nVelo> {answer}\n      [{r.usage.prompt_tokens} prompt + {r.usage.completion_tokens} completion = {r.usage.total_tokens} tokens]")

if len(sys.argv) > 1:
    ask(" ".join(sys.argv[1:]))
else:
    print("Chat with Velo (type 'quit' to leave)")
    while (q := input("\nYou> ").strip()).lower() not in ("quit", "exit", ""):
        ask(q)

  2. Read it top to bottom. Three things to notice: DefaultAzureCredential() uses your signed-in identity (Cloud Shell or az login); get_openai_client() returns a client already pointed at your project; and the history list is the conversation memory, appended on every turn.

  3. Run it with a question, then without arguments for a loop:

    python chat_client.py "A customer asks whether the Velocity Volt can tow a small trailer. What should I tell them?"
python chat_client.py       # interactive; type quit to leave

  4. Edit it. Change temperature to 1.2 and ask for a tagline; change the system prompt to make Velo answer in Spanish; add response_format={"type": "json_object"} and the extraction instructions from Part 5. Each is a one-line change. That is the whole point of a lightweight client.

Troubleshooting

The Python client fails with 401 / "PermissionDenied" / "does not have authorization"

Your identity needs a data-plane role on the Foundry resource: Azure AI User (or Azure AI Developer). Race control assigns it; the command is az role assignment create --assignee <your-upn> --role "Azure AI User" --scope $(az cognitiveservices account show -n $NAME -g $RG --query id -o tsv). Roles take a minute or two to propagate.

429 "Rate limit exceeded"

You hit your deployment's 10K tokens per minute, usually by pasting a very long context or running in a loop. Wait a minute, or shorten the prompt. The playground shows the same error in red.

DefaultAzureCredential cannot find a credential (on your laptop)

Run az login first. In Cloud Shell this never happens; the shell is already signed in.

The playground shows gpt-5-mini and no temperature slider

Reasoning models do not expose temperature. Switch the deployment selector at the top of the playground to gpt-4-1-mini.

Quick quiz

Which message should contain "You are Velo… if you do not know, say so"?

The system message (Instructions). It sets persona and rules for the whole conversation; user messages carry the questions.

In chat.completions.create(model="gpt-4-1-mini", …), what is model?

Your deployment name, not the catalog model name. In Foundry the two can differ; code always uses the deployment.

You want valid JSON every time from a GPT model. What do you set?

response_format={"type": "json_object"} (and say "return JSON" in the prompt), with a low temperature.

What does the Foundry SDK's get_openai_client() give you?

An OpenAI-compatible client already authenticated to your project with your Entra ID identity, so you call chat.completions, responses, images and so on without handling keys or endpoints yourself.

Which is the better fix for invented warranty terms: a stern system prompt, or grounding?

Grounding. A stern prompt reduces bluffing; only real context lets the model answer correctly and cite it. Use both.

Pit wall debrief · what you learned

  • The system prompt sets the job; user prompts give context and format; history is the only memory.
  • Temperature and top_p shape randomness; max tokens bounds length and cost; you watched both in the playground and in the raw JSON.
  • Ungrounded models hallucinate specifics; grounding with the real text, plus "answer only from this, cite it", fixes it.
  • JSON mode and few-shot examples turn a chat model into a component other software can call.
  • A lightweight client is AIProjectClient(endpoint, DefaultAzureCredential()).get_openai_client() plus a messages list.
