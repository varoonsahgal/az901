The day before

  1. One subscription, Owner access for you. Students need Contributor (to create resource groups and resources) and Azure AI User (data-plane access to Foundry projects and agents) at subscription scope. Put their sign-in names in students.txt, one per line, and run the helper:

    curl -sO https://varoonsahgal.github.io/az901/pit-crew/race_control.sh && chmod +x race_control.sh
./race_control.sh prep                 # registers providers, prints the quotas that matter
./race_control.sh roles students.txt   # Contributor + Azure AI User per student

    If everyone signs in with one shared account instead, grant that account the two roles once; the student-number scheme still keeps resources apart.

  2. Check quotas in East US 2. The numbers that bound class size on a fresh subscription (yours may differ; the prep command prints them):

    QuotaTypical limitPer studentFits
    OpenAI.Standard.gpt4.1-mini (TPM)200K10K20 exactly, with no headroom for your own demo: deploy your gpt-4.1-mini in another region (we used East US), or request a quota increase in advance (Azure portal → Quotas → Azure OpenAI; usually approved within hours), or tell students to deploy at 8K.
    OpenAI.GlobalStandard.gpt4.1-mini (TPM)200K—A second pool: half the class can deploy Global Standard instead if Standard runs dry.
    OpenAI.GlobalStandard.gpt-audio-mini (TPM)30K1K20 with room.
    AIServices.GlobalStandard.FLUX.2-pro (capacity units)30120 with room; each unit is one request per minute.
    OpenAI.Standard.text-embedding-3-large (TPM)350K+10KFine.
    AIServices.S0.AccountCount1001Fine.
    OpenAI.Standard.gpt4.1 (TPM)50K—Only you need it, for the prebuilt-invoice demo in Lap 6.

  3. Build your own garage (student s00) by running Lap 0 yourself in East US (not East US 2) so your deployments do not eat the class's Standard quota, plus for Lap 6: a gpt-4-1 deployment and the Content Understanding defaults mapping prebuilt-analyzer-completion to it. Run every lab once; it takes about three hours and surfaces anything Microsoft changed since this site was built.

  4. Whiteboard: student numbers s01–s20 next to names; the site URL; the three rules (your number is your namespace; S0 never F0; small deployments). Headphones for Lap 4.

  5. Cloud Shell works without a storage account in ephemeral mode. If your tenant blocks it, students can use a laptop with az and Python 3.10+; every command on the site is plain bash.

Cleanup

./race_control.sh status      # what is left
./race_control.sh cleanup     # delete every rg-ai901-* and purge soft-deleted Foundry names
az role assignment list --query "[?roleDefinitionName=='Azure AI User' || roleDefinitionName=='Contributor'].{who:principalName,role:roleDefinitionName}" -o table   # revoke student roles afterwards if the subscription lives on
⚠️
Soft delete

Deleting a resource group soft-deletes the Foundry resource for 48 hours and keeps its DNS name reserved. If you run the course again next week with the same student numbers, purge first or the names will be "already taken".

How this site was verified, and what the screenshots are

  • Every API call on this site was executed against a real subscription on 1–2 November 2026 (Azure CLI 2.90, Python 3.11, Foundry SDK azure-ai-projects 2.10). The JSON responses are in downloads/results/.
  • Screenshots of results (the cards with captions, fields, sentiment bars, agent conversations) are the real responses, rendered into a consistent card design so they are readable on a projector. Terminal screenshots show real CLI output; the instructor's resource names were replaced with the sample student s07 and the region with East US 2, which is where students work.
  • There are no screenshots of the Foundry or Azure portal. The portal requires an interactive browser session, which the build process did not have. Portal steps follow the official Microsoft Learning exercises for the same features, using their UI labels (New Foundry, Discover → Models, Instructions, Save as agent, Publish → Preview web app, Voice mode, Build → Services → Content Understanding). Expect drift; the Cloud Shell path on every page is the one that was executed.
  • Things learned the hard way, already baked into the labs: Content Understanding's preview API versions return 410 (use 2025-11-01); analyzer IDs cannot contain hyphens; prebuilt-invoice requires gpt-4.1 or gpt-5-family models while custom analyzers accept gpt-4.1-mini; the agents API rejects the deprecated agent property in favour of agent_reference; FLUX deployments are rate-limited to one request per minute per capacity unit; a freshly deployed FLUX.2-pro in East US 2 answered 404/429 for a long stretch while FLUX-1.1-pro in East US worked at once, so Lap 5 tells students to fall back to FLUX-1.1-pro if that happens; gpt-audio-mini and FLUX had quota in East US 2 but not East US on this subscription; Azure Machine Learning and AutoML were built and then removed because AI-901 dropped classic ML.
  • Photos are public domain or CC0 from Wikimedia Commons (see credits); documents, audio, video and datasets were generated for the course; concept-car images were generated with FLUX models.
