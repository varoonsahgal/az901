The story so far

Finance keys 900 service invoices a month by hand. The used-car team retypes window stickers. Marketing cannot find the clip where the Volt's charging time is mentioned. The pit crew's answer is one service with one habit: send a file, get fields.

Part 0 · The idea in five minutes

Content UnderstandingA Foundry Tool that takes documents, images, audio and video and returns structured results: markdown of the content plus fields you define or that a prebuilt analyzer defines. It is the successor to the separate Document Intelligence, Video Indexer and speech-transcription pipelines for extraction work.
AnalyzerThe unit of configuration. Prebuilt analyzers (prebuilt-invoice, prebuilt-receipt, prebuilt-idDocument, prebuilt-callCenter, prebuilt-videoSynopsis…) know their fields already. Custom analyzers start from a base (prebuilt-document, prebuilt-image, prebuilt-audio, prebuilt-video) and add your field schema.
Field schemaEach field has a type (string, number, integer, boolean, date, array, object), a method (extract = copy what is on the page, with a source and confidence; generate = write it, e.g. a summary; classify = pick one of your enum values) and a description, which is the prompt the model follows.
Models behind itOCR and layout need no model. Field extraction uses a GPT completion model and an embedding model that you deploy and register once per resource (PATCH /contentunderstanding/defaults). The prebuilt field analyzers want a full gpt-4.1-class model (gpt-4-1, from Lap 5 or Part 1); custom analyzers are happy with gpt-4.1-mini.
The async patternPOST …/analyzers/{id}:analyzeBinary returns 202 Accepted and an Operation-Location header; you GET that URL until status is Succeeded. Creating a custom analyzer works the same way.
Result shaperesult.contents[]: one entry per document, image, audio track or video segment, each with markdown, fields (valueString, valueNumber, valueArray…, plus confidence and source for extracted fields), and for media, startTimeMs/endTimeMs, transcripts and key frames.

Send a file, get fields.Documents, images, audio and video all come back in the same shape: markdown of the content, plus the typed fields you named. One habit, four modalities.

Content Understanding is a Foundry Tool that borrows your models.Lap 0 split the resource into two kinds of AI: prebuilt tools such as Vision, which need no deployment, and models such as gpt-4.1-mini, which do. Content Understanding sits on both sides. Its own reading layer (OCR, layout, transcription) works like Vision; turning that text into fields calls deployments you own, so you deploy them and tell the service which ones to use. That is all of Part 1.

Why not just ask gpt-4.1-mini?

Lap 5 showed gpt-4.1-mini a photo and Lap 2 got JSON out of it, so a fair question is what this service adds. It wraps the model in everything a production extraction job needs:

Prompting a model yourself (Laps 2 and 5)Content Understanding (this lap)
InputText and images you put in the promptDocuments, images, audio and video files, any length
ReadingThe model reads the raw pixels or textOCR, layout, transcription and key frames first, then the model reads clean markdown
OutputWhatever text the model writes; you parse it and hopeTyped fields from your schema: numbers are numbers, dates are dates
Can I check it?No source, no confidenceExtracted fields carry a page location and a confidence score
ReuseCopy the prompt into every appSave it once as an analyzer; every app calls it by ID

Why it mattersFor one photo in a chat, prompting is fine. For 900 invoices a month that land in a finance system, you want the same fields, the same types and a confidence to route doubtful ones to a person. On the exam, "extract fields from forms, recordings or video" points here; "describe or reason about an image" points to a multimodal model.

Exam lens

Documents and forms → prebuilt analyzers or a custom schema on prebuilt-document. Images → a custom schema on prebuilt-image (classify / describe). Audio → transcript, then fields such as summary, topics, sentiment (prebuilt-callCenter). Video → shots, key frames, transcript, synopsis (prebuilt-video, prebuilt-videoSynopsis). Part 3 · Build your own analyzer · the window sticker

Prebuilt analyzers know other people's paperwork. The Velocity window sticker is ours: no prebuilt knows that the used-car team wants the VIN, the total MSRP and the options with their prices. So you build an analyzer: pick a base, name the fields, and describe each one in plain English.

An analyzer is a saved recipe, not a model.It is a few lines of JSON: a base that does the reading (here prebuilt-document, the layout you just saw), a field schema, and the name of a model to fill it in. Nothing is trained. Change a description and re-create the analyzer, and the next run follows the new instruction.

Prebuilt analyzerCustom analyzer
FieldsChosen by Microsoft (InvoiceNumber, TotalAmount…)Chosen by you (VIN, TotalMSRP…)
You writeNothing; call it by IDA base, a schema and a description per field
Pick it whenThe paperwork is common: invoices, receipts, IDs, tax forms, callsThe paperwork is yours, or you want different fields

The portal door

The playground's Customize in CU Studio button (top right) opens Content Understanding Studio, a separate site for building your own analyzers with clicks. Explore it if you finish early. Here you write the analyzer as JSON in Cloud Shell, because JSON shows most clearly what matters: each field's type, its method and the description the model follows.

  1. Describe the fields you want. The description is the instruction; method says whether to copy, write or choose. Each description is a small prompt, so the Lap 2 rules apply: be specific ("17-character" beats "the VIN"). The models line asks for gpt-4.1-mini by its catalog name; the Part 1 registration maps that to your gpt-4-1-mini deployment. Custom analyzers accept mini, so the cheaper engine does this job.

Part 4 · Images · lot photos into a table

A second analyzer of your own, this time on photographs: base it on prebuilt-image, use classify with an enum where you want controlled values, and generate for free text. The script creates it, waits, then runs four lot photos through it.

Why another image toolLap 5 read photos twice: Azure AI Vision returned fixed tags and boxes, and gpt-4.1-mini wrote a free-text listing. This is the third option, between the two: the model looks at the photo, but its answer must fit columns you defined. Use it when the photos are going into a spreadsheet or inventory system, not a chat. Only the base changed from Part 3; the PUT, the wait and the analyze call are the same.

One row per photo (our screenshot has six). The traffic photo counted 38 vehicles; the convertible became a "coupe" because that was the closest allowed value, which is exactly what an enum is for.

Classify keeps a column clean. Generate fills it with whatever the model says.With an enum, "SUV", "suv" and "sport utility" can only ever come back as suv, so you can filter and count the column. The cost is precision: a convertible has to become the nearest allowed value. Add the value to the enum if it matters to the business.

Part 6 · The lightweight app

Everything above is one function: send bytes, poll, print fields. extract_info.py is that function with a command line. Any analyzer, any modality.

Why pollThe video step above waits 45 seconds, and a long contract could take minutes, which is longer than one HTTP request should stay open. So the service answers at once with 202 and a ticket (Operation-Location), and the app checks the ticket every few seconds. Every sleep in this lap's curl commands was a guess at how long that takes; the script replaces the guess with a loop. It signs in with the resource key from Lap 0, like the other Foundry Tool calls.

curl -sO https://varoonsahgal.github.io/az901/pit-crew/extract_info.py
python extract_info.py velocityWindowSticker window-sticker.png
python extract_info.py prebuilt-audio narration.mp3
"""Lap 6 · Information extraction with Azure Content Understanding (a Foundry Tool).
Works on documents, images, audio and video. This script sends a file to an analyzer and prints the fields.

Run:  python extract_info.py prebuilt-invoice service-invoice.pdf
      python extract_info.py velocityWindowSticker window-sticker.png
      python extract_info.py prebuilt-audio narration.mp3
Needs: pip install requests
Env:   FOUNDRY_ENDPOINT_AI (https://<resource>.services.ai.azure.com)   AI_KEY
"""
import os, sys, time, mimetypes, requests

analyzer, path = (sys.argv + ["prebuilt-invoice", "service-invoice.pdf"])[1:3]
base = os.environ["FOUNDRY_ENDPOINT_AI"].rstrip("/") + "/contentunderstanding"
ver = "api-version=2025-11-01"
headers = {"Ocp-Apim-Subscription-Key": os.environ["AI_KEY"]}
ctype = mimetypes.guess_type(path)[0] or "application/octet-stream"

# 1) Start the analysis (long-running operation → 202 + Operation-Location)
r = requests.post(f"{base}/analyzers/{analyzer}:analyzeBinary?{ver}", headers={**headers, "Content-Type": ctype}, data=open(path, "rb").read())
r.raise_for_status()
op = r.headers["Operation-Location"]
print(f"submitted {path} to {analyzer} …", end="", flush=True)

# 2) Poll until it finishes
while True:
    time.sleep(3); result = requests.get(op, headers=headers).json()
    print(".", end="", flush=True)
    if result["status"].lower() in ("succeeded", "failed"): break
print(" " + result["status"])
if result["status"].lower() == "failed": sys.exit(result.get("error"))

def value(f):
    for k in ("valueString", "valueNumber", "valueInteger", "valueBoolean", "valueDate"):
        if k in f: return f[k]
    if "valueArray" in f: return [value(i) for i in f["valueArray"]]
    if "valueObject" in f: return {k: value(v) for k, v in f["valueObject"].items()}
    return f.get("content")

Troubleshooting

"Failed to start analysis… 400", DeploymentIdNotFound, or curl: option : blank argument where content is expected

Almost always a brand-new gpt-4-1. Content Understanding can take ten to fifteen minutes to see a new deployment reliably, and until then calls fail on and off with DeploymentIdNotFound (in our test run, about half of them for the first quarter hour). In Cloud Shell the failed POST returns no Operation-Location, so $OP is empty and the next curl prints the "blank argument" message. Run the step again; extract_info.py shows the real error. In the portal select Run analysis again. Still failing after fifteen minutes? Check the Configure panel (or the PATCH …/defaults) names your gpt-4-1 exactly. Lap 5 Part 1 step 3 avoids all of this by deploying an hour early.

The fields come back null, or jq says "Cannot iterate over null"

The analysis was still running when you read it: .status says Running. Run the last curl "$OP" … line again after a few seconds, or use extract_info.py, which waits for you.

Portal path: "Model deployments required" every time I pick Document fields

The models were never applied. Select Deploy models, choose your three deployments in the Configure panel, and finish with Apply changes; closing the panel without it changes nothing.

Portal path: gpt-4.1 will not deploy, or says no quota

Check the deployment type is Global Standard, not Standard: that is where this subscription's gpt-4.1 quota is (1,000K tokens per minute in East US 2). Keep the rate limit at 40000 so twenty-three people fit.

"The 'analyzerId' cannot contain '-'"

Use letters and digits only: velocityWindowSticker, not velocity-window-sticker.

"Defaults have not yet been set to 'prebuilt-analyzer-embedding'"

Run the PATCH …/defaults from Part 1 (or set Embedding model in the portal Configure panel) after deploying text-embedding-3-large. Custom document analyzers need both a completion and an embedding mapping.

"Provided model 'gpt-4.1-mini' is not supported by this analyzer"

Some prebuilt analyzers (prebuilt-invoice, prebuilt-receipt…) accept only gpt-4.1 or gpt-5-family models; GET …/analyzers/prebuilt-invoice shows supportedModels. Map prebuilt-analyzer-completion to your gpt-4-1 (portal: Chat completion model in the Configure panel), or use a custom schema on prebuilt-document, which accepts gpt-4.1-mini.

410 "The requested API version has been retired"

The preview versions (2024-12-01-preview, 2025-05-01-preview) are gone. Use api-version=2025-11-01.

Status Failed with RateLimit / 429 inside the error

The completion deployment ran out of tokens per minute, typically on video, and the analysis fails after several minutes. First check the defaults point prebuilt-analyzer-completion-mini at gpt-4-1, not your 8K gpt-4-1-mini: re-run the Part 1 PATCH (portal: Chat completion model (mini) in the Configure panel). Then check your gpt-4-1 is at 40K, not 20K (az cognitiveservices account deployment list -n $NAME -g $RG -o table); re-running the deploy command with --sku-capacity 40 raises it in place. Then wait a minute and retry.

404 "Analyzer … with status 'Failed' is not ready"

Creation failed (usually a model mapping problem). GET …/analyzers/<id> shows the error; DELETE it, fix the JSON, PUT again.

Quick quiz

Which base analyzer would you use for a custom schema over photographs?

prebuilt-image. Documents use prebuilt-document; audio and video use prebuilt-audio and prebuilt-video.

What is the difference between extract and generate field methods?

Extract copies a value that appears in the content and returns its source and confidence; generate has the model compose a value (a summary, a count) with no source. Classify picks one of your enum values.

You POST to :analyzeBinary and get 202. What next?

GET the URL in the Operation-Location header until status is Succeeded, then read result.contents.

Which prebuilt analyzer gives a summary, topics and sentiment for a recorded call?

prebuilt-callCenter (on top of the transcript that prebuilt-audio produces).

Why does field extraction need model deployments but OCR does not?

OCR and layout are classic vision models inside the service. Turning text into typed fields, writing summaries and classifying use a GPT completion model (and embeddings for retrieval over long documents), which you supply from your own deployments.

Pit wall debrief · what you learned

  • Content Understanding is one API for documents, images, audio and video: analyzers, field schemas, async operations, typed results with confidence.
  • It is a Foundry Tool that borrows your models: its own layer reads the file (OCR, layout, transcription), then your registered deployments turn the text into fields. Deploy, then register.
  • Compared with prompting a model directly, it adds the reading layer, typed fields, sources and confidence, and a reusable analyzer ID. An analyzer is a saved recipe, not a trained model.
  • Prebuilt analyzers for common forms, runnable in the portal playground (Document fields, Call center, OCR, Layout); custom analyzers (base + schema) for your own paperwork and photos.
  • Field methods: extract (with source), generate (composed), classify (enum). Models are registered once per resource.
  • Audio gives transcripts and call-center fields; video gives key frames, transcripts and a synopsis.
  • extract_info.py is the lightweight extraction app: send, poll, print.
