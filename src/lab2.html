The story so far

Sales wants Velo: an assistant on the website and in the car that answers like a good service advisor, never bluffs about warranties, and can hand a tidy ticket to the service team. You have a deployed model from Lap 0. Now you shape it.

Part 0 · The idea in five minutes

System prompt (instructions)The message the user never sees: who the model is, what it may and may not do, how to answer. In the Foundry playground this is the Instructions box. Most "the bot behaves badly" problems are system-prompt problems.
User promptThe question or task. Good user prompts give context, say what format they want, and give an example when the format matters.
Conversation historyPrevious user and assistant messages sent back with every call. That is the model's only memory. "New chat" clears it.
Few-shot examplesTwo or three worked examples inside the prompt. The cheapest way to teach a format or a classification scheme; no training needed.
GroundingPutting the facts the answer must come from inside the prompt (or giving an agent a search tool), and instructing "answer only from this". The cure for invented warranty terms.
Structured outputAsking for JSON (and enforcing it with response_format) so a program, not a human, can read the answer.

A system prompt is a job description. A user prompt is a ticket. History is the only memory.

Three ways to talk to the same deployment, which you will use in that order: the playground (click), the REST API with curl (see the raw JSON), and the Foundry SDK from Python (the lightweight client the exam describes).

🎯
Exam lens

"Effective" prompts on the exam means: a clear role and constraints in the system prompt, specific user prompts with context and desired format, examples for tricky formats, and grounding data for facts. Parameters: temperature and top_p control randomness, max tokens bounds length and cost, stop sequences end output. The SDK pattern to recognise is AIProjectClient + DefaultAzureCredential + get_openai_client() + chat.completions.create(model=<deployment name>, messages=[…]).

Part 2 · Shape Velo in the playground

  1. Open the playground. Open ai.azure.com (with New Foundry on) and your project. Select Models in the left menu, then your deployment gpt-4-1-mini, then the Playground tab. Not in the list? Deploy it as in Lap 0 (Part 3, Deploy the model), with Custom settings and 10K tokens per minute.

    Get your bearings. On the left: the Model: gpt-4-1-mini bar with a + (compare), a sliders icon (Parameters) and a key icon; below it the Instructions box and Tools. On the right: the chat, with a New chat icon at its top right, and the buttons Continue in code, Save as agent and Compare models.

    Why the deploymentThe playground talks to your deployment, exactly as your code will. Whatever you tune here, you can carry into code with one button (step 6).

  2. Ask, with no instructions: My Summit's tire pressure light came on this morning. What should I do? Read it. Reasonable, generic, and it does not know what a Summit is.

  3. Give it a job. Select New chat. In the Instructions box 1, paste the system prompt we used:

    You are Velo, the friendly in-car and dealership assistant for Velocity Motors. Be concise, warm, and practical. Use plain language. If a question involves safety, put the safety step first. If you do not know something specific about Velocity Motors, say so.

    Ask the tire-pressure question again. Now the first words are "safely pull over", and it ends by offering to help find the nearest service center.

    Why it matters"Safety step first" is a business rule, written once, applied to every customer. Your service advisors follow a script; this is Velo's.

    Same model, same question, different job description, different answer.Nothing was trained or deployed. Four sentences in the Instructions box changed what the customer gets.

  4. History is the memory. Ask a follow-up without repeating context: And if it comes back on tomorrow? The model answers in context because the playground resends the conversation. Select New chat and ask the same follow-up: now it has no idea what "it" is. That is history, made visible.

  5. Parameters. Select the sliders icon next to the model name 1. The Parameters panel opens:

    • Past messages included (10): how many earlier messages the playground resends with each question. It is the dial behind step 4. What would 0 do to the follow-up?
    • Max Completion Tokens: a hard cap on answer length (and cost).
    • 2Temperature: set it to 0.
    • Top P: leave at 1.

    Select New chat and ask three times: Write a six-word tagline for the Velocity Volt electric sedan. Reply with the tagline only. Then set Temperature to 1.3 (or the maximum the slider allows) and ask three more times. Compare with our run:

    Why temperatureA warranty answer must be the same every time a customer asks; a launch tagline should not be. Low for facts and extraction, higher for copywriting.

    Also try Max Completion Tokens at 20 and watch the answer stop mid-sentence: it is cut, not shortened. Then put Max Completion Tokens back and set Temperature back to 0: Parts 4 and 5 want repeatable answers.

  6. Continue in code. Select Continue in code. A dialog, Call gpt-4-1-mini in code, shows your Project endpoint, the API key (masked), Language (choose Python) and Authentication method (Entra ID authentication). The sample it writes has this shape:

    base_url="https://…/openai/v1",
    api_key=get_bearer_token_provider(DefaultAzureCredential(), "https://ai.azure.com/.default"))
response = client.responses.create(model="gpt-4-1-mini", input="…")

    Why Entra IDNo key in the code: the token comes from your signed-in identity and its role on the resource. It uses the Responses API; Parts 3 and 6 use Chat Completions. Both reach the same deployment, and the exam expects you to recognise both.

Part 3 · The same call as raw HTTP

This is the call the playground just made for you. Underneath it is one REST endpoint; seeing it once makes every SDK obvious. The messages array carries the roles; the response has choices (the answers) and usage (the tokens you pay for).

curl -s "$AOAI_ENDPOINT/openai/deployments/$CHAT_MODEL/chat/completions?api-version=2024-10-21" \
  -H "api-key: $KEY" -H "Content-Type: application/json" -d '{
  "messages": [
    {"role": "system", "content": "You are Velo, the Velocity Motors assistant. Be concise."},
    {"role": "user", "content": "Write a six-word tagline for the Velocity Volt."}
  ],
  "temperature": 0.7, "max_tokens": 40
}' | jq '{answer: .choices[0].message.content, usage}'

The same API with Part 2's full Velo instructions and the tire-pressure question (temperature 0.4) gives the safety-first answer you saw in the playground, plus the token count:

Part 4 · Stop Velo from bluffing · grounding

  1. Catch the bluff. Put the plain Velo prompt from Part 2 back in Instructions, check Temperature is 0, select New chat, and ask:

    I'm buying a Certified Pre-Owned Velocity. How many points is the CPO inspection, how long is roadside assistance, and is there a deductible for warranty repairs?

    Our run answered with total confidence: a 150-point inspection, roadside assistance for 24 months from the date of purchase, and no deductible. Velocity Motors' real warranty guide says:

    QuestionVelo saidThe guide says
    CPO inspection150 points172 points (section 6)
    Roadside assistance24 months5 years, unlimited miles (section 5)
    DeductibleNoneNone (section 7)

    Two of three are invented, and the third is right only by luck: the model has never seen the guide. Notice that its instructions already said "If you do not know something specific about Velocity Motors, say so". It bluffed anyway. An earlier version of this lab asked about the Volt battery warranty; on a later run the model answered 8 years / 100,000 miles and matched our guide, only because that is the industry norm.

    A right answer from a guess is still a guess.The customer cannot tell which of the three claims was invented, and neither can you without the guide. This is the reason Lap 3 exists.

  2. Ground it. Replace the Instructions 1 with exactly this:

    You are Velo. Answer ONLY using the context below. If the answer is not in the context, say you don't know. Cite the section number. CONTEXT (Velocity Motors Warranty Guide, 2026): Section 5 Roadside assistance: 24/7 towing, flat-tire change, jump start and lockout, included for 5 years with unlimited miles. Section 6 Certified Pre-Owned: 12-month / 12,000-mile comprehensive warranty after the basic warranty ends; a 172-point inspection is performed before sale. Section 7 Claims: no deductible for warranty repairs; loaner vehicles for repairs over 4 hours.

    Select New chat and ask the same question. Now 2: "172-point inspection… 5 years with unlimited miles… no deductible… (Section 5, Section 6, Section 7)".

    Why in the InstructionsThe customer never sees the context, and it rides along with every question. That is what an app does with the right pages of a manual: fetch them, put them in the prompt, and tell the model to stay inside them.

  3. Ask past the edge. Same instructions: Does the warranty cover a cracked windshield? The context says nothing about glass, so a well-grounded model says it does not know from this context. Pasting the right sections by hand works for three sections; the real guide has dozens. In Lap 3 file search does the "find the right section" step for you.

Same grounding, by API: the context goes in the system message, the question in the user message.

curl -s "$AOAI_ENDPOINT/openai/deployments/$CHAT_MODEL/chat/completions?api-version=2024-10-21" \
  -H "api-key: $KEY" -H "Content-Type: application/json" -d '{
  "messages": [
    {"role": "system", "content": "You are Velo. Answer ONLY using the context below. If the answer is not in the context, say you do not know. Cite the section number. CONTEXT (Velocity Motors Warranty Guide, 2026): Section 5 Roadside assistance: 24/7 towing, flat-tire change, jump start and lockout, included for 5 years with unlimited miles. Section 6 Certified Pre-Owned: 12-month / 12,000-mile comprehensive warranty after the basic warranty ends; a 172-point inspection is performed before sale. Section 7 Claims: no deductible for warranty repairs; loaner vehicles for repairs over 4 hours."},
    {"role": "user", "content": "How many points is the CPO inspection, how long is roadside assistance, and is there a deductible for warranty repairs?"}
  ],
  "temperature": 0
}' | jq -r '.choices[0].message.content'

Run it again with the system message cut down to You are Velo, the Velocity Motors assistant. and compare. An earlier run of ours did the same with a battery-warranty excerpt (sections 4.2 to 4.4): ungrounded on the left, grounded and citing sections on the right.

Grounding gives the model something to be right about.And when the context is silent, "I don't know" is not a failure. It is the feature you paid for.

Part 6 · Your first chat app with the Foundry SDK

The playground is for exploring; a product needs code. The Foundry SDK (azure-ai-projects) connects to your project endpoint with your own identity, then hands you an OpenAI-compatible client. No key in the code.

  1. In Cloud Shell, get the script (all pit-crew scripts are in pit-crew-scripts.zip; this fetches just one):

    curl -sO https://varoonsahgal.github.io/az901/pit-crew/chat_client.py
cat chat_client.py
    """Lap 2 · A lightweight chat client built with the Foundry SDK.

Run:  python chat_client.py "your question"      (or no argument for an interactive loop)
Needs: pip install azure-ai-projects azure-identity   and   az login
Env:   PROJECT_ENDPOINT  (Foundry project endpoint, e.g. https://<resource>.services.ai.azure.com/api/projects/<project>)
       CHAT_MODEL        (deployment name, default gpt-4-1-mini)
"""
import os, sys
from azure.identity import DefaultAzureCredential          # uses your az login — no keys in code
from azure.ai.projects import AIProjectClient

endpoint = os.environ["PROJECT_ENDPOINT"]
model = os.environ.get("CHAT_MODEL", "gpt-4-1-mini")

project = AIProjectClient(endpoint=endpoint, credential=DefaultAzureCredential())
client = project.get_openai_client()                        # an OpenAI-compatible client, already authenticated

SYSTEM = ("You are Velo, the friendly assistant for Velocity Motors dealerships. "
          "Be concise and practical. Safety first. If you don't know a Velocity-specific fact, say so.")
history = [{"role": "system", "content": SYSTEM}]

def ask(text):
    history.append({"role": "user", "content": text})
    r = client.chat.completions.create(model=model, messages=history, temperature=0.5, max_tokens=300)
    answer = r.choices[0].message.content
    history.append({"role": "assistant", "content": answer})
    print(f"\nVelo> {answer}\n      [{r.usage.prompt_tokens} prompt + {r.usage.completion_tokens} completion = {r.usage.total_tokens} tokens]")

if len(sys.argv) > 1:
    ask(" ".join(sys.argv[1:]))
else:
    print("Chat with Velo (type 'quit' to leave)")
    while (q := input("\nYou> ").strip()).lower() not in ("quit", "exit", ""):
        ask(q)

  2. Read it top to bottom. Three things to notice: DefaultAzureCredential() uses your signed-in identity (Cloud Shell or az login); get_openai_client() returns a client already pointed at your project; and the history list is the conversation memory, appended on every turn.

  3. Run it with a question, then without arguments for a loop:

    python chat_client.py "A customer asks whether the Velocity Volt can tow a small trailer. What should I tell them?"
python chat_client.py       # interactive; type quit to leave

  4. Edit it. Change temperature to 1.2 and ask for a tagline; change the system prompt to make Velo answer in Spanish; add response_format={"type": "json_object"} and the extraction instructions from Part 5. Each is a one-line change. That is the whole point of a lightweight client.

Troubleshooting

The Python client fails with 401 / "PermissionDenied" / "does not have authorization"

Your identity needs a data-plane role on the Foundry resource: Foundry User (or Azure AI Developer). Race control assigns it; the command is az role assignment create --assignee <your-upn> --role "Foundry User" --scope $(az cognitiveservices account show -n $NAME -g $RG --query id -o tsv). Roles take a minute or two to propagate.

429 "Rate limit exceeded"

You hit your deployment's 10K tokens per minute, usually by pasting a very long context or running in a loop. Wait a minute, or shorten the prompt. The playground shows the same error in red.

DefaultAzureCredential cannot find a credential (on your laptop)

Run az login first. In Cloud Shell this never happens; the shell is already signed in.

Playground: "ERR_BAD_REQUEST Project not found"

An intermittent portal error, usually on the first message after New chat. Send the same message again; it goes through.

Playground: my instructions disappeared

The playground does not save them. If you left the page (Foundry asks Leave without saving?), paste them again from this page. To keep them for good, use Save as agent; Lap 3 starts from there.

Grounded Velo still invents an answer, or answers without a section

Check that the context went into Instructions in full (the box scrolls), that Temperature is 0, and that you started a New chat: old ungrounded answers in the history pull the model back toward its guesses.

The playground shows gpt-5-mini and no temperature slider

Reasoning models do not expose temperature. Open the Model: dropdown at the top of the left pane and pick gpt-4-1-mini, or go back to Models and open that deployment.

Quick quiz

Which message should contain "You are Velo… if you do not know, say so"?

The system message (Instructions). It sets persona and rules for the whole conversation; user messages carry the questions.

In chat.completions.create(model="gpt-4-1-mini", …), what is model?

Your deployment name, not the catalog model name. In Foundry the two can differ; code always uses the deployment.

You want valid JSON every time from a GPT model. What do you set?

response_format={"type": "json_object"} (and say "return JSON" in the prompt), with a low temperature.

What does the Foundry SDK's get_openai_client() give you?

An OpenAI-compatible client already authenticated to your project with your Entra ID identity, so you call chat.completions, responses, images and so on without handling keys or endpoints yourself.

Which is the better fix for invented warranty terms: a stern system prompt, or grounding?

Grounding. A stern prompt reduces bluffing; only real context lets the model answer correctly and cite it. Use both.

Pit wall debrief · what you learned

  • The system prompt sets the job; user prompts give context and format; history is the only memory.
  • Temperature and top_p shape randomness; max tokens bounds length and cost; you watched both in the playground and in the raw JSON.
  • Ungrounded models hallucinate specifics; grounding with the real text, plus "answer only from this, cite it", fixes it.
  • JSON mode and few-shot examples turn a chat model into a component other software can call.
  • A lightweight client is AIProjectClient(endpoint, DefaultAzureCredential()).get_openai_client() plus a messages list.
