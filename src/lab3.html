The story so far

Yesterday's Velo invented a two-year battery warranty. Today you give it the real guide and the discipline to use it. The service desk also wants a version that can do arithmetic on invoices without rounding errors. Both are agents: the same model, plus instructions, plus tools.

Part 0 · The idea in five minutes

AgentA named, versioned definition: a model, instructions (its standing system prompt), and a list of tools it may use. You talk to it through a conversation that it keeps for you.
Foundry Agent ServiceThe managed runtime inside your project that stores agents, runs them, calls their tools, keeps conversation state, traces every step, and exposes them to apps and channels.
ToolsFile search (your documents, chunked and embedded into a vector store), Code interpreter (a Python sandbox), Web search / Bing grounding, Function tools (your own APIs), MCP servers, Azure AI Search, OpenAPI tools, browser automation.
ConversationThe thread of messages between a user and an agent. The service stores it; your client just passes its id. "New conversation" is a fresh memory.
agent_referenceHow a client names the agent it wants: {"name": "velo-warranty-expert", "version": "1", "type": "agent_reference"} sent with a Responses API call. The older agent property is deprecated and the service rejects it.
PublishTurn an agent into something people can reach: a preview web app, Microsoft 365 Copilot and Teams, or your own app through the SDK.

A chat model answers. An agent finishes the job.It decides which tool to call, calls it, reads the result, and keeps going until the task is done. The model is the same; the loop is new.

🎯
Exam lens

Agentic AI is the workload where the model chooses actions. On the exam: an agent = model + instructions + tools; File search gives it your documents (grounding); Code interpreter lets it compute; function tools call your systems; conversations hold context; a client references the agent by name and version through the Foundry SDK's OpenAI client and the Responses API. Responsible-AI points: instructions are guardrails, tools get least privilege, keep a human in the loop for consequential actions, use tracing and evaluations.

The knowledge file · velocity-warranty-guide.md (what the agent will read)
# Velocity Motors Warranty Guide — 2026 edition (excerpt)

## 1. Basic (bumper-to-bumper) coverage
All new Velocity vehicles are covered for 4 years or 50,000 miles, whichever comes first, against defects in materials or workmanship. Wear items (brake pads, wiper blades, tires, bulbs) are excluded after 12 months / 12,000 miles.

## 2. Powertrain coverage
Engine, transmission, drive axles and (for hybrids) the hybrid control module are covered for 6 years or 70,000 miles.

## 3. Corrosion
Perforation from rust is covered for 7 years with unlimited miles. Surface rust is not covered.

## 4. Electric vehicle components (Velocity Volt)
4.1 Drive unit and on-board charger: 8 years or 100,000 miles.
4.2 High-voltage battery: 8 years or 100,000 miles, whichever comes first, against defects AND against capacity loss below 70% of the original rated capacity.
4.3 Transferability: all Velocity warranties transfer automatically to subsequent owners at no cost for the remainder of the original term.
4.4 Exclusions: damage from flooding, racing or track use, or charging with non-approved chargers is not covered.

## 5. Roadside assistance
24/7 roadside assistance (towing to the nearest Velocity dealer, flat-tire change, jump start, lockout) is included for 5 years with unlimited miles.

## 6. Certified Pre-Owned (CPO)
CPO vehicles receive a 12-month / 12,000-mile comprehensive warranty that begins when the original basic warranty ends, plus the remainder of the powertrain coverage. A 172-point inspection is performed before sale.

## 7. How to make a claim
Bring the vehicle to any authorized Velocity Motors dealer. There is no deductible for warranty repairs. Loaner vehicles are provided for repairs expected to take more than 4 hours.

  5. Add knowledge. In the left pane expand Tools (sometimes labelled Knowledge and Tools), select Add → File search (or Files), upload velocity-warranty-guide.md, and confirm. The portal creates a vector store: the file is split into chunks and embedded so the agent can retrieve the right section. Select Save again.

  6. Select New chat and ask the battery question again, then Is there a deductible for warranty repairs, and do I get a loaner car?, then the trap: Does the warranty cover a cracked windshield from a rock on the highway?

    Three things happened. It answered from the guide with section numbers. It used the tool (the response contains a file_search_call item before the message). And on the windshield question it reasoned from section 1's wording to "not covered" rather than inventing a glass clause.   8. Optional: Add → Web search, then ask Find the nearest Velocity Motors dealer to Dayton, Ohio. (It will find real dealers of other brands; Velocity is fictional. The point is seeing a second tool get called.) Remove it afterwards to keep the warranty expert honest.

Part 3 · Give an agent a calculator · Code interpreter

Language models are poor at arithmetic because they predict tokens, not sums. The Code interpreter tool gives an agent a Python sandbox: it writes the code, runs it, and reports the result. Models predict digits; calculators compute them.

  1. Create a second agent, velo-data-analyst, model gpt-4-1-mini, instructions: You are a data analyst for Velocity Motors. Use the code interpreter to compute answers precisely and show the Python you ran. Under Tools → Add → Code interpreter. Save.

  2. Ask: Service invoice lines: pads 189.00, rotors 2 x 120.00, labor 2.5 h x 145.00, rotation 29.95, supplies 18.50. Sales tax 7.5%. What is the total?

    Subtotal $839.95, tax $63.00, total $902.95, computed, not guessed. (Lap 6 extracts the same numbers from the invoice PDF; together that is an automated audit.) You can also upload a CSV and ask for a chart; the sandbox returns image files.

Our version of that sample, with a conversation and a loop:

    curl -sO https://varoonsahgal.github.io/az901/pit-crew/agent_client.py
cat agent_client.py
    """Lap 3 · A lightweight client for the agent you built in the Foundry portal.

Run:  python agent_client.py "your question"      (or no argument for an interactive loop)
Needs: pip install azure-ai-projects azure-identity   and   az login
Env:   PROJECT_ENDPOINT   AGENT_NAME (default velo-warranty-expert)   AGENT_VERSION (default 1)
"""
import os, sys
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

project = AIProjectClient(endpoint=os.environ["PROJECT_ENDPOINT"], credential=DefaultAzureCredential())
client = project.get_openai_client()
agent = {"name": os.environ.get("AGENT_NAME", "velo-warranty-expert"), "version": os.environ.get("AGENT_VERSION", "1"), "type": "agent_reference"}

conversation = client.conversations.create()          # the agent remembers everything in this conversation
print(f"Talking to agent {agent['name']} v{agent['version']} · conversation {conversation.id[:18]}…")

def ask(text):
    r = client.responses.create(conversation=conversation.id, input=text, extra_body={"agent_reference": agent})
    tools = [o.type for o in r.output if o.type != "message"]          # e.g. file_search_call, code_interpreter_call
    print(f"\n{agent['name']}> {r.output_text}")
    if tools: print(f"   [tools used: {', '.join(tools)}]")

if len(sys.argv) > 1:
    ask(" ".join(sys.argv[1:]))
else:
    while (q := input("\nYou> ").strip()).lower() not in ("quit", "exit", ""):
        ask(q)

    from azure.ai.projects.models import PromptAgentDefinition, FileSearchTool, CodeInterpreterTool
openai = project.get_openai_client()
vs = openai.vector_stores.create(name="velocity-warranty-kb")
openai.vector_stores.files.upload_and_poll(vector_store_id=vs.id, file=open("velocity-warranty-guide.md", "rb"))
agent = project.agents.create_version(agent_name="velo-warranty-expert",

conversation = openai.conversations.create()
r = openai.responses.create(conversation=conversation.id, input="Does the Volt battery warranty transfer?",
    extra_body={"agent_reference": {"name": agent.name, "version": str(agent.version), "type": "agent_reference"}})
print(r.output_text)

Troubleshooting

400 "The 'agent' property is deprecated. Use 'agent_reference' instead."

Older samples send extra_body={"agent": {...}}. The service now wants agent_reference with name, version and type. Our script already does.

The agent answers from general knowledge instead of the file

Check the file finished indexing (the vector store shows the file as completed), that the tool is attached to the saved version you are calling, and that the instructions say "only from the file". Start a new chat; old conversations keep old context.

"Model deployment not found" or a quota error when creating the agent

The Model list shows deployments in this project's resource. Pick gpt-4-1-mini; if it is missing, go back to Lap 0 and deploy it. If the portal insists on deploying a gpt-5 model and quota fails, choose Browse more models and select your existing deployment.

Python: PermissionDenied on the project endpoint

Agents require an Entra ID role on the Foundry resource: Azure AI User (or Azure AI Developer). Keys do not work for the project endpoint. Ask race control.

Quick quiz

What three things define an agent in Foundry?

A model, instructions, and tools (plus a name and version). Conversations are state the service keeps for it.

Which tool lets the agent answer from your PDF and markdown files?

File search: files are chunked and embedded into a vector store the agent queries. Code interpreter runs Python; Web search browses the internet; function tools call your APIs.

How does a Python client say which agent to use?

By passing extra_body={"agent_reference": {"name": …, "version": …, "type": "agent_reference"}} to responses.create on the OpenAI client returned by AIProjectClient.get_openai_client().

Why did the agent compute $902.95 correctly when a plain model might not?

It used the Code interpreter tool to run Python instead of predicting digits token by token.

Fastest way to let a colleague try your agent without code?

Publish → Preview web app in the agent playground.

Pit wall debrief · what you learned

  • An agent is a model plus instructions plus tools, run and remembered by the Foundry Agent Service.
  • File search turns documents into knowledge the agent can cite; Code interpreter turns it into a reliable calculator.
  • Conversations carry context; new chat means new memory.
  • Publish gives you a preview web app; the Foundry SDK gives you a client in a handful of lines, pinned to an agent name and version with agent_reference.
  • Guardrails for agents are instructions, least-privilege tools, tracing and a human in the loop.
