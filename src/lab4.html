The story so far

Customer Experience has a folder of reviews in five languages, a stack of service tickets full of personal data, and a press release nobody has time to read. Engineering wants the in-car assistant to talk. Every one of these is a Foundry Tool call away, and all of them are already in your resource from Lap 0.

Part 0 · The idea in five minutes

Azure AI LanguageOne endpoint, many kinds of analysis: language detection, sentiment (with opinion mining), key phrases, named entities, PII, summarization, plus conversational language understanding and question answering. Prebuilt; no training needed.
Azure AI TranslatorText translation between 100+ languages, several targets in one call, transliteration (script conversion) and dictionary lookups. Document translation too.
Speech recognitionSpeech-to-text: real time or batch, 100+ languages, timestamps, confidence, punctuation and display vs lexical text, diarization, custom speech for jargon.
Speech synthesisText-to-speech with neural voices; SSML controls voice, language, style, rate, pitch and pauses; custom neural voice for a brand voice.
Voice mode (Voice Live)Azure Speech built into a Foundry agent: switch it on and the agent listens and speaks in the playground and in apps, with no audio code of your own.
Multimodal audio modelA model such as gpt-audio-mini that takes audio in and returns audio and text in one call. No separate recognition or synthesis step; less control over the voice, more natural turn-taking.
🎯
Exam lens

Match the technique to the output: key phrases → a list of topics; entities → typed things (person, date, product, PII); sentiment → positive/negative/neutral/mixed with scores; summarization → extractive (sentences copied) or abstractive (new text). Speech: recognition is audio→text, synthesis is text→audio, SSML tunes synthesis. Two ways to answer a spoken question: the Speech pipeline (STT → model → TTS) or one multimodal audio model. Know the trade-off: pipeline = control and cheaper models; multimodal = simpler and more natural.

Part 2 · Text analysis on customer reviews

In the portal you redact a real-looking service ticket, then detect and translate a German complaint. The Cloud Shell tab covers the same techniques by API, plus the ones the portal does not show, starting with sentiment.

You could ask gpt-4-1-mini "is this review positive?". So why a separate Language service?In Lap 2 you made the model classify comments with a few-shot prompt, and it worked. Language gives you the same answers as a fixed JSON shape with confidence scores and character offsets, the same every time, with no prompt to write and no deployment to size. Reach for the model when the question is open-ended; reach for Language when you need the same structured answer on forty thousand reviews.

🔑
The playgrounds use your sign-in, not the key

The Language, Speech and Translator playgrounds call the service as you. If one fails with CheckAccess request is invalid…, your account is missing the Cognitive Services User role: see Troubleshooting. The Cloud Shell tab uses the key and works meanwhile.

  1. Find the Language playgrounds. Open ai.azure.com and your project. In the left nav select Services. Under Explore services you see tiles for Document Intelligence and Content Understanding, Speech, Language and Translator, plus Featured playgrounds below. Select Language. Its playgrounds are Language Detection, Text PII Redaction, Document PII Redaction, Text Analytics for Health and Conversational PII Redaction.

    Why ServicesThese are the prebuilt Foundry Tools, already inside the resource you made in Lap 0. Nothing to deploy and nothing to train: you send text, you get structured results.

    There is no sentiment, key-phrase or entity playground here; step 5 sends you to the API for those.

  2. Redact a service ticket. Open Text PII Redaction. In Input text paste the ticket below (you can also pick from the Sample list or upload a file), then select Detect.

    Service ticket 4471. Customer Dana Whitfield (dana.whitfield@example.com, 937-555-0142) dropped off her 2024 Velocity Strata on 12 March 2026. Address: 1200 Brown St, Dayton, OH 45409. Paid the deposit with card 4111 1111 1111 1111.

    The text comes back with each identifier masked and labelled: PersonType, Person, Email, PhoneNumber, Date, Address and CreditCardNumber. The Redact PII switch toggles between masked and original. On the right, the Response tab lists every entity with its Type, Confidence (Dana Whitfield: Person, 99%), Offset and Length; JSON and Code show the raw call.

    Why redactService tickets get copied into CRMs, emails and now AI prompts. Redact before you store or forward one, and a leak exposes asterisks, not a customer's card number.

    It left ticket number 4471 and "2024 Velocity Strata" alone: not personal data. It did flag "Customer" as a PersonType, a role rather than an identity. The configuration panel (API version, Model version, Language, Select types to include) decides which types count; a service team that needs the drop-off date could keep Date unmasked.

    Offset and Length turn a highlighter into an API.Your code gets the exact position of every identifier, so it can mask, hash or vault each one before the ticket is saved. The JSON tab is the same response the Cloud Shell tab gets from curl.

  3. Detect a language. Go back to Language and open Language Detection. Paste this review from a customer in Germany and run it:

    Der Volt fährt sich wunderbar leise, aber das Navigationssystem stürzt ständig ab und der Händler in München hat mich nie zurückgerufen.

    It should come back as German, with a confidence score.

    Why detect firstReviews arrive in five languages. Knowing the language routes each one to the right market team, or to translation, before anyone has to read it.

  4. Translate it. In the left nav select Services → Translator → Text Translation. Keep Model: Azure-MT and the Translator tab (the Code tab shows the call). Leave Source text on Auto Detect, paste the same German review, set the target language to English, and select Translate.

    Expect: The Volt drives wonderfully quietly, but the navigation system keeps crashing and the dealer in Munich never called me back. The Configuration panel offers Tone and Gender, but only for LLM-based translation, not Azure-MT.

    Why it mattersThat one sentence holds two problems for two teams: a navigation bug for Engineering and a missed callback for the Munich dealer. Nobody in Dayton reads German; now they do not have to.

  5. Sentiment, key phrases, entities and summaries: switch tabs. The exam asks about all of these. Select the Cloud Shell path tab above and run its step 1 (sentiment with opinion mining) and the lightweight app text_analysis.py at the end of it.

This is what the playgrounds did for you, plus the techniques the portal does not show. Azure AI Language has one synchronous endpoint; you change the kind. Start with sentiment on a grumpy review, then look at the six reviews we analysed.

  1. Sentiment with opinion mining. The document score says "negative"; opinion mining says what was negative (the cupholders). The jq filter keeps only the score; drop it to see the targets under sentences.

    curl -s -X POST "$ENDPOINT/language/:analyze-text?api-version=2024-11-01" -H "Ocp-Apim-Subscription-Key: $KEY" -H "Content-Type: application/json" -d '{
  "kind": "SentimentAnalysis", "parameters": {"opinionMining": true},
  "analysisInput": {"documents": [{"id": "1", "language": "en", "text": "Meh. It is a car. It goes. The cupholders are too small for my travel mug."}]}
}' | jq '.results.documents[0] | {sentiment, confidenceScores}'

    In the six-review card, review 1 is mixed: the engine is praised and the infotainment system is not. Opinion mining attaches a sentiment to each target.

    Sentiment tells you how they feel. Opinion mining tells you about what.A product team cannot act on "mixed". It can act on "the infotainment system crashed".

  2. Key phrases and entities. Change "kind" to KeyPhraseExtraction and then EntityRecognition (no parameters needed). Key phrases give you the talking points; entities give you typed things: Organization, Product, Location, DateTime, Quantity, Person.

  3. PII detection. Kind PiiEntityRecognition. The service returns every personal identifier it found and a redacted copy of the text, ready to store. This is the privacy-and-security principle as an API call.

  4. Language detection. Kind LanguageDetection, with no language field in the documents. On reviews from Germany, Spain, Japan, France and the US, every one came back at confidence 1.00, ready to route to the right market team or to translation.

  5. Summarization is asynchronous. You POST a job to $ENDPOINT/language/analyze-text/jobs?api-version=2024-11-01 with tasks ExtractiveSummarization and AbstractiveSummarization, then GET the operation-location URL until status is succeeded. On the Volt press release, extractive picked three real sentences; abstractive wrote a new two-sentence summary.

  6. Translator is a separate host that takes the same key plus a region header. Every call so far went to your own $ENDPOINT; Translator's text API lives on one global address shared by all of Azure, so the region header tells it which resource your key belongs to. One call, six languages:

    curl -s -X POST "https://api.cognitive.microsofttranslator.com/translate?api-version=3.0&from=en&to=de&to=ja&to=es&to=fr&to=hi&to=zh-Hans" \
  -H "Ocp-Apim-Subscription-Key: $KEY" -H "Ocp-Apim-Subscription-Region: $LOC" -H "Content-Type: application/json" \
  -d '[{"text":"Welcome to Velocity Motors. The 2027 Velocity Volt charges from 10 to 80 percent in 18 minutes."}]' | jq

    "Terrible experience at the Dayton dealership. I waited three hours for an oil change. Nobody apologized.",
    "Picked up a certified pre-owned Velocity Strata for $21,400 last month. Great value. Priya, the service advisor, was fantastic.",

print("\n── Entities ──")

Part 3 · Make the car talk · Azure Speech

Part 2 worked on text. A driver does not type, so Speech is the bridge: speech-to-text turns a voice into text that Language or a model can use, and text-to-speech turns the answer back into a voice. It is another prebuilt Foundry Tool on the same resource and key, still with no deployment.

  1. Find the Speech playgrounds. In the left nav select Services → Speech. Its playgrounds are Voice Live, Speech to Text, Text to Speech, Text to Speech Avatar and Speech Translation.

  2. Give Velo a voice. Open Text to Speech. The left panel holds Input mode (plain text or SSML), Voice, Model, Language skill and Tuning. Set:

    • 1Voice: leave the default, Ava. The model is Dragon HD Latest (marked Emotion enabled) and Language skill is Auto detect.
    • Replace the text on the right with Velo's welcome:
    Welcome back to your Velocity Volt. The cabin is warming to seventy degrees, your battery is at eighty-two percent, and you have two hundred and ten miles of range. Your next service is due in two thousand one hundred miles. Drive safely!
    • 2Select Play. Each word highlights as it is spoken. Download saves the audio; Sample rate is 24kHz.

    Why pick a voice deliberatelyThe voice is the car's personality, heard every time a driver starts it. A brand chooses it the way it chooses a logo. Pick two other voices from the list and play the same text: which one sounds like Velocity?

    The sample-text chips (Customer service, Casual chat, News report…) show the same voice in other moods. Switch Input mode to SSML to control style, pauses or a mid-sentence language change: the markup the Cloud Shell tab posts.

  3. Listen to a driver. Download user-brake-question.wav, a driver asking Velo about a warning light. Open Speech to Text and check the settings:

    • Speech Service: Real-time transcription. Model: Azure Speech (Default).
    • Language: English (United States). Leave Language identification off; with it on you would list candidate languages.
    • Output format Detailed, and an empty Phrase list for now.

    Upload the WAV file (or use New Recording to try your own voice). The Transcript tab shows the text, with JSON and Call service beside it and an audio player below:

    Hey Velo, my break warning light just came on while I was driving. Is it safe to keep driving to the dealership or should I pull over?

    Read it again: "my break warning light". Break and brake sound identical, so the recogniser picked the more common word.

    The recogniser hears sounds; the spelling is a guess.For a car company, "brake" is the word that matters most. A Phrase list tells Speech which words your business uses, with no training; custom speech goes further.

This is what the playgrounds did for you, plus SSML and a three-step pipeline app.

  1. Text-to-speech with SSML. Write the SSML to a file and POST it to the regional TTS endpoint. The header X-Microsoft-OutputFormat chooses the audio format.

    Listen to the two recordings we made. The first is the plain welcome message; the second uses an express-as style, emphasis, a break and two lang tags in one utterance.

    List the voices available to you (1,000+ across 150+ locales) with curl -s https://$LOC.tts.speech.microsoft.com/cognitiveservices/voices/list -H "Ocp-Apim-Subscription-Key: $KEY" | jq '.[] | select(.Locale=="en-US") | .ShortName' | head.

  2. Speech-to-text. Send a WAV to the regional STT endpoint. We sent the welcome message back in, saved as a 16 kHz WAV (velo-ava.wav):

    curl -sO https://varoonsahgal.github.io/az901/downloads/velo-ava.wav
curl -s "https://$LOC.stt.speech.microsoft.com/speech/recognition/conversation/cognitiveservices/v1?language=en-US&format=detailed" \
  -H "Ocp-Apim-Subscription-Key: $KEY" -H "Content-Type: audio/wav; codecs=audio/pcm; samplerate=16000" --data-binary @velo-ava.wav | jq

    "Seventy degrees" came back as "70°" and "two thousand one hundred" as "2100": the display text applies inverse text normalization; the lexical field keeps the spoken words. Both are in the detailed response.

  3. The pipeline app. speech_pipeline.py recognises a question from a WAV file with the Speech SDK, asks your gpt-4-1-mini deployment, and speaks the answer into another WAV. File in, file out, so it runs in Cloud Shell without a microphone.

    curl -sO https://varoonsahgal.github.io/az901/pit-crew/speech_pipeline.py
curl -sO https://varoonsahgal.github.io/az901/downloads/question.wav     # "Hey Velo, my brake warning light just came on…"
python speech_pipeline.py question.wav answer.wav
    """Lap 4 · Speech in → model → speech out, with Azure Speech (a Foundry Tool).

Run:  python speech_pipeline.py question.wav answer.wav
Needs: pip install azure-cognitiveservices-speech openai azure-identity azure-ai-projects
Env:   AI_KEY  SPEECH_REGION (e.g. eastus2)  PROJECT_ENDPOINT  CHAT_MODEL
Works in Cloud Shell because it reads and writes .wav files instead of using a microphone.
"""
import os, sys
import azure.cognitiveservices.speech as speechsdk
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

in_wav, out_wav = (sys.argv + ["question.wav", "answer.wav"])[1:3]
speech = speechsdk.SpeechConfig(subscription=os.environ["AI_KEY"], region=os.environ["SPEECH_REGION"])

# 1) Speech recognition (speech-to-text)
rec = speechsdk.SpeechRecognizer(speech_config=speech, audio_config=speechsdk.audio.AudioConfig(filename=in_wav))
heard = rec.recognize_once()
print(f"heard   : {heard.text!r}  ({heard.reason.name})")

# 2) Ask the model
project = AIProjectClient(endpoint=os.environ["PROJECT_ENDPOINT"], credential=DefaultAzureCredential())
r = project.get_openai_client().chat.completions.create(model=os.environ.get("CHAT_MODEL", "gpt-4-1-mini"), max_tokens=120, messages=[
    {"role": "system", "content": "You are Velo, the in-car assistant for Velocity Motors. Safety first. Reply in under 40 spoken-friendly words."},
    {"role": "user", "content": heard.text}])
answer = r.choices[0].message.content
print(f"answer  : {answer}")

# 3) Speech synthesis (text-to-speech) with a neural voice
speech.speech_synthesis_voice_name = "en-US-AvaMultilingualNeural"
synth = speechsdk.SpeechSynthesizer(speech_config=speech, audio_config=speechsdk.audio.AudioOutputConfig(filename=out_wav))
result = synth.speak_text_async(answer).get()
print(f"spoken  : {out_wav} ({len(result.audio_data)//1024} KB, {result.reason.name})")
    heard   : 'Hey Velo, my break warning light just came on while I was driving.'  (RecognizedSpeech)
answer  : Please safely pull over and stop your car. Check your brake fluid level and ensure the parking brake is fully released. If the light stays on, do not drive—contact roadside assistance immediately. Safety first!
spoken  : answer.wav (435 KB, SynthesizingAudioCompleted)

    The recognizer heard "break warning light", and recognize_once stopped at the first pause, so only the first sentence arrived. Context still carried the model to a sensible answer. A car product would add a phrase list or a custom speech model.

    The middle of this pipeline is your Lap 2 chat app.Step 2 is the same chat.completions.create call on the same gpt-4-1-mini deployment, signed in with Entra ID through the project. Steps 1 and 3 are Speech, signed in with the key. One app, two kinds of AI, two credentials: exactly the split from Lap 0.

Part 4 · One model that listens and speaks · gpt-audio-mini

Now the other architecture: one model that hears the question and speaks the answer. This part is code on both paths: the gpt-audio-mini model page says Playground isn't available for this model yet.

  1. Deploy the audio model. It is Global Standard only, and capacity 1 (1K tokens per minute) is enough for one person: audio costs about 10 tokens per second in and out. Prefer clicks? Deploy it the Lap 0 way (Models → Deploy → Deploy a base model, search gpt-audio-mini, Custom settings, deployment name gpt-audio-mini, Global Standard, 1000 tokens per minute) and skip the command.

    az cognitiveservices account deployment create --name $NAME --resource-group $RG \
  --deployment-name gpt-audio-mini --model-name gpt-audio-mini --model-version 2025-10-06 --model-format OpenAI \
  --sku-name GlobalStandard --sku-capacity 1 -o table

    Why a second deploymentLanguage and Speech needed none, because they are prebuilt tools. gpt-audio-mini is a model, and code never calls a model, only a deployment (Lap 0). Your gpt-4-1-mini cannot take audio in, so the audio model needs its own deployment, with its own name and its own TPM. It is Global Standard because, as the Lap 0 table said, that is the only type this model offers here.

  2. Ask it the brake question. Send the same spoken question straight to the model and get spoken audio plus a transcript back. On the portal path, fetch the question into Cloud Shell first: curl -sO https://varoonsahgal.github.io/az901/downloads/question.wav.

    Read the code below: it is the Lap 2 chat call again, sent to the openai.azure.com host from Lap 0. Only two things changed: the user message holds audio instead of text, and modalities asks for audio back as well as text.

    curl -sO https://varoonsahgal.github.io/az901/pit-crew/talk_to_velo.py
python talk_to_velo.py question.wav reply.wav
    """Lap 4 · Respond to a SPOKEN prompt with a multimodal audio model (gpt-audio-mini).
One model hears the question and speaks the answer — no separate speech-to-text step.

Run:  python talk_to_velo.py question.wav reply.wav
Needs: pip install openai
Env:   AOAI_ENDPOINT (https://<resource>.openai.azure.com)  AI_KEY  AUDIO_MODEL (default gpt-audio-mini)
"""
import os, sys, base64
from openai import AzureOpenAI

in_wav, out_wav = (sys.argv + ["question.wav", "reply.wav"])[1:3]
client = AzureOpenAI(azure_endpoint=os.environ["AOAI_ENDPOINT"], api_key=os.environ["AI_KEY"], api_version="2025-01-01-preview")

r = client.chat.completions.create(
    model=os.environ.get("AUDIO_MODEL", "gpt-audio-mini"),
    modalities=["text", "audio"], audio={"voice": "alloy", "format": "wav"},
    messages=[
        {"role": "system", "content": "You are Velo, the in-car assistant for Velocity Motors. Safety first, then one or two short steps. Under 50 words."},
        {"role": "user", "content": [{"type": "input_audio", "input_audio": {"data": base64.b64encode(open(in_wav, "rb").read()).decode(), "format": "wav"}}]}])

msg = r.choices[0].message
open(out_wav, "wb").write(base64.b64decode(msg.audio.data))
print("Velo said:", msg.audio.transcript)
print(f"saved {out_wav} · tokens: {r.usage.prompt_tokens_details.audio_tokens} audio in, {r.usage.completion_tokens_details.audio_tokens} audio out")
    Velo said: Safety first: Pull over safely and contact roadside assistance or your dealership immediately. Then have the brakes inspected before continuing your drive.
saved reply.wav · tokens: 81 audio in, 199 audio out

Troubleshooting

gpt-audio-mini will not deploy: "InsufficientQuota" or no capacity left

The subscription allows 20 gpt-audio-mini deployments in East US 2, one per student, so in a class of more than twenty the last few can run out. Tell your instructor rather than retrying. Meanwhile do the rest of Part 4 with the recorded reply in Part 3, or watch a neighbour's run: the point is one model hearing and speaking, and that is visible on any screen.

Playground error: "CheckAccess request is invalid because: This resource is not ready to accept requests"

The playgrounds use your Entra sign-in, not the key, and your account lacks the Cognitive Services User role on your resource. Ask race control to grant it, wait 2–5 minutes for the role to reach the service, and reload the playground. The Cloud Shell tab works meanwhile, because it uses the key.

Translator returns 401 while Language works

Translator's global host needs the extra header Ocp-Apim-Subscription-Region: eastus2 so it knows which resource the key belongs to.

STT returns "InitialSilenceTimeout" or an empty DisplayText

The WAV must be 16-bit PCM, 16 kHz, mono. Generate it with the TTS format riff-16khz-16bit-mono-pcm or convert with ffmpeg: ffmpeg -i in.m4a -ar 16000 -ac 1 out.wav.

speech_pipeline.py: "ImportError: libssl" or the Speech SDK will not load

In Cloud Shell run pip install --user --upgrade azure-cognitiveservices-speech; on some Linux images you also need sudo apt-get install -y libssl-dev libasound2. The REST calls in Part 3 need nothing.

gpt-audio-mini: "DeploymentNotFound" or 429

Check the deployment name is exactly gpt-audio-mini and that AOAI_ENDPOINT points at your own resource. A 429 at capacity 1 means you spoke for a long time; wait a minute or raise capacity to 2.

Voice mode will not start a session

The browser needs microphone permission and HTTPS (the portal is). Try a different browser; make sure the agent has a saved model and that your role on the resource includes Foundry User.

Quick quiz

You want a list of the main topics customers mention. Which technique?

Key phrase extraction. Entities give typed things; sentiment gives polarity; summarization gives prose.

A review says the engine is great but the screen crashes. What does sentiment analysis return, and what tells you which part was bad?

Document sentiment mixed; opinion mining attaches positive to "engine" and negative to "infotainment system".

Which summary type can contain sentences that are not in the original?

Abstractive. Extractive only selects existing sentences.

Which SSML element switches the voice's language mid-sentence?

<lang xml:lang="de-DE"> (with a multilingual voice). <voice> changes the voice; <mstts:express-as> the style; <break> adds a pause.

A product must answer spoken questions with the least custom code. Pipeline or multimodal audio model?

Multimodal audio model (or Voice mode on an agent): one call in, audio out. Choose the pipeline when you need a specific brand voice, custom vocabulary, or cheaper text models.

Speech to text writes "break warning light" for a driver who said "brake". What is the quickest fix that needs no training?

Add brake to a phrase list, which biases recognition toward your business's words. A custom speech model trained on automotive audio goes further but takes data and time.

Which service feature returns a redacted copy of a ticket?

Azure AI Language PII detection (PiiEntityRecognition), via redactedText.

Pit wall debrief · what you learned

  • Azure AI Language: language detection, sentiment with opinion mining, key phrases, entities, PII with redaction, extractive and abstractive summarization; Translator for languages.
  • Azure Speech: recognition (display vs lexical text, confidence) and synthesis (neural voices, SSML), both as REST calls or through the Speech SDK; Voice mode puts them inside an agent.
  • Two architectures for a talking assistant: STT → model → TTS, or one multimodal audio model such as gpt-audio-mini. Voice mode is the pipeline, managed inside an agent.
  • Language, Translator and Speech are prebuilt tools: no deployment, fixed output, scores you can act on. A model answers anything but must be deployed, and an audio model needs its own deployment.
  • One app can mix both, with two credentials: speech_pipeline.py uses the key for Speech and Entra ID for the model.
  • Three lightweight apps: text_analysis.py, speech_pipeline.py, talk_to_velo.py.
